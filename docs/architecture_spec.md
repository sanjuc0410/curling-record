# architecture_spec.md — 컬링 기량 기록부 (구글 시트판)

- 확정일: 2026-10-05
- 목적: 시트(A~F)별 훈련 중 코치들이 **로그인 없이(링크 + PIN)** 휴대폰으로 동시에 평가를 기록하고, 결과를 구글 시트 한 곳에 모은다.
- 사용 범위: 학교 공식 프로그램이 아닌 팀 운영용. 개인정보 보안 수준은 "기본"으로 확정 (사용자 확인).

## 1. 문제 정의 (확정)

| 단계      | 내용                                                                      |
| :---      | :---                                                                      |
| 문제 상황 | 시트별 훈련 중 여러 코치가 동시에, 로그인 없이 평가를 기록해야 함          |
| 해결 상태 | 링크 + PIN 접속 → 시트(A~F)·팀·선수 배정 → 회차별 1~5점 → 시트 한 곳에 누적 |
| 피드백    | 저장 상태(저장 중/동기화 시각/연결 끊김·대기 n건), 선수별 진행률(6/12)      |

## 2. 기능 점검구 (모듈 분리선)

| 모듈        | 파일         | 역할                                                        | 교체 시 영향          |
| :---        | :---         | :---                                                        | :---                  |
| 화면(UI)    | `Index.html` | 시트 보드, 점수판, 팀 현황, 선수 분석, 특이사항, 설정        | 저장 어댑터만 호출     |
| 저장 어댑터 | `Index.html` | `put/del/putSkills` → 대기열 → `google.script.run.api` 호출  | 저장소 교체 시 여기만  |
| API 관문    | `Code.gs`    | `api(pin, action, payload)` 단일 진입점, PIN·동작 검증       | —                     |
| 시트 저장소 | `Code.gs`    | 탭별 upsert/delete, `LockService` 잠금                      | —                     |
| 보고서      | `Code.gs`    | 메뉴 `평가결과 표 만들기` (회차 점수를 행으로 펼침)          | 원본 데이터 불변       |

허용 동작: `load`, `put`, `del`, `putSkills` (그 외는 `bad_action`)

## 3. 데이터 점검구 (구글 시트 탭)

| 탭         | 열 구성                                              | 키 / 비고                        |
| :---       | :---                                                 | :---                             |
| `teams`    | id · data · 수정시각 · 팀 이름                        | id = `t_…`                       |
| `players`  | id · data · 수정시각 · 이름 · 팀 · 포지션              | id = `p_…`                       |
| `sessions` | id · data · 수정시각 · 날짜 · 시트 · 팀 · 세션 이름     | data에 `sheet`, `playerIds`, `items[{itemId,skillId,name,reps}]` |
| `records`  | id · data · 수정시각 · 날짜 · 시트 · 팀 · 선수 · 종합   | id = `세션id__선수id` (시트 간 충돌 없음) |
| `notes`    | id · data · 수정시각 · 날짜 · 선수 · 분류 · 내용        | 분류: 부상·통증/컨디션/기술/태도·멘탈/기타 |
| `config`   | id · data · 수정시각                                 | id = `skills` (평가 기능·항목·기본 횟수) |
| `로그`     | 시각 · 동작 · 내용                                    | 최대 1,000행 유지                |
| `평가결과` | 날짜 · 시트 · 팀 · 선수 · 포지션 · 기능 · 항목 · 회차 점수 · 항목 평균 · 메모 | 보고용, 메뉴로 재생성 |

- 원본은 `data`(JSON) 열. 오른쪽 열은 읽기용이며 앱에 반영되지 않음.
- 점수 계산: 회차(1~5) 평균 = 항목 점수 → 같은 기능 항목 평균 = 기능 점수 (`records.data.skillScores`).
- 분석은 기능마다 "가장 최근 값"과 "직전 값"을 비교 (세션마다 평가 항목이 달라도 비교 가능).

## 4. 감지 점검구

| 감지 지점     | 처리                                                              |
| :---          | :---                                                              |
| 저장 요청     | 기기 대기열(`localStorage`)에 먼저 저장 → 화면 즉시 반영 → 서버 전송 |
| 전송 실패     | 상단 빨간 배너 + "연결 끊김 · 대기 n건", 5초 후 자동 재시도         |
| 동기화        | 20초마다 / 화면 복귀 시 `load`, 마지막 동기화 시각 표시             |
| 잘못된 요청   | `bad_col/bad_id/bad_data/too_big` → 대기열에서 제거 + 안내 메시지   |
| 서버 예외     | `로그` 탭에 시간·동작·스택 기록, 화면에 "서버 오류" 메시지          |

## 5. 보안 점검구 (기본 수준으로 확정)

| 항목        | 기준                                                               |
| :---        | :---                                                               |
| 접속        | 코치 PIN 1개 (숫자 4~12자리), 스크립트 속성 `COACH_PIN`에 저장       |
| 하드코딩    | 코드에 PIN·키·URL·실제 학생 데이터 없음                              |
| 무차별 대입 | 10분 안에 PIN 20회 오류 시 10분 잠금 (`CacheService`)               |
| PIN 교체    | 메뉴로 변경 → 기존 기기는 다음 요청에서 PIN 재입력                   |
| 입력 검증   | 탭 화이트리스트, id 정규식 `^[A-Za-z0-9_-]{1,120}$`, JSON 45,000자 제한 |
| 수식 주입   | `= + - @` 로 시작하는 읽기용 값은 앞에 `'` 를 붙여 글자로 저장        |
| 테스트 데이터 | 가상 데이터(예시팀, 학생A~D)만 사용, 설정에서 일괄 삭제              |
| 배포        | 실행 계정 = 소유자, 액세스 = 모든 사용자 (교육청 계정이 막히면 개인 계정) |

## 6. 확장 후보 (미구현)
- 투구 순서 모드(리드→스킵 자동 이동), 성공/실패 체크 입력, 시트 로테이션(시간대별 배정)
- 약점 기능 → 훈련 드릴 추천, 출결·훈련 일지, 경기 샷 퍼센티지 기록
